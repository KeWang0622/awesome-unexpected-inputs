# What has actually been checked

[Collection](../README.md) · [Method](methodology.md)

**Independent device tests recorded in this repository: 0.** All initial entries are source-reviewed. A working release, an author's demonstration and an independently reproduced setup are different kinds of evidence.

The automated checks validate required fields, supported status values, source dates, canonical project identity, generated file freshness, SVG structure, and local links/anchors. Regression tests exercise failure cases and catalog behavior. These checks do not run third-party software, verify remote page claims, benchmark performance or certify hardware compatibility.

## How to report a useful reproduction

Use the test-report issue form. Record:

| Field | What makes the result useful |
| --- | --- |
| Project | Stable catalog ID and upstream release/commit |
| Hardware | Exact model, revision, peripherals and connection |
| Software | OS, firmware, drivers and relevant app versions |
| Route | Steps followed and any departure from upstream documentation |
| Result | The specific action that worked or failed; avoid “works perfectly” |
| Limits | Lag, tracking failures, unavailable features or setup barriers observed |
| Evidence | A redacted photo, recording, log or reproducible notes, with reuse permission if supplied |
| Date | When the test was performed |

A failure report is useful even if the cause is unknown. Do not generalize one device's result to an entire device family. Reviewer approval should link the evidence and describe its exact scope.

## Publication checks

Use the repository's **Catalog checks** workflow for the latest commit's structural result. Its badge is not a hardware certification. The source-review date belongs to each record and changes only when the sources are inspected again.
